## Root Cause

The APCR telemetry is generated by `SagittalVelocityDampedBalanceController.compute()` and returned in `sagittal_diag`, but the telemetry wiring in `simulate_hierarchical_controller.py` does not copy these fields to the simulation-level telemetry dictionary.

Looking at lines 3818-3856 of `simulate_hierarchical_controller.py`:
```python
tau_sagittal_wheel_balance, sagittal_diag = balance_core_controllers["sagittal_wheel_balance"].compute(...)
# Only adds:
# - support_position_error_m
# - support_position_error_scaled_m
# - position_authority_scale
# - com_position_error_sagittal_m
# - pitch_x_ref_rad
# - pitch_x_error_rad
# - transient_detected / transient_by_* / pitch_rate_boost_factor
# - transient_capture_mode
# - sagittal_axis_x/y_initial
# - raw_com_vx/vy
# - projected_sagittal_velocity_m_s
# - actual_sagittal_velocity_passed_to_controller_m_s
# - support_center_x/y
```

Missing APCR fields from `sagittal_diag`:
- active_pitch_crossing_*
- bias_cancel_*

## Impact

- Cannot analyze APCR state transitions row-by-row
- Cannot verify APCR activation timing
- Cannot check state machine behavior (NEUTRAL, CROSS_FROM_POSITIVE, CROSS_FROM_NEGATIVE)
- Cannot verify recovery gate behavior
- Cannot verify safety override behavior

## Evidence

1. CSV header check: 523 columns total, no `active_pitch_crossing_*` columns
2. Controller code has 28 APCR-specific telemetry fields defined (lines 1507-1537)
3. Telemetry wiring only copies subset of fields (lines 3834-3856)

## Recommended Fix

Add APCR fields to telemetry wiring in `simulate_hierarchical_controller.py`:

```python
# After line 3855 (after support_center_y)
sagittal_diag["active_pitch_crossing_enabled"] = sagittal_diag.get("active_pitch_crossing_enabled", False)
sagittal_diag["active_pitch_crossing_state"] = sagittal_diag.get("active_pitch_crossing_state", "NEUTRAL")
sagittal_diag["active_pitch_crossing_active"] = sagittal_diag.get("active_pitch_crossing_active", False)
# ... etc for all APCR fields
```
